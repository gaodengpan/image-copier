## 3. Phase 0: 研究与分析 (Research & Analysis)

### 3.1 决策记录

#### 决策: 加密密钥派生方法
- **Rationale**: 需要从环境变量提供的字符串密钥派生出固定长度的加密密钥
- **选项1**: PBKDF2 (推荐) - 广泛使用，安全性好，但较慢
- **选项2**: scrypt - 安全性高，内存困难
- **选项3**: bcrypt - 主要用于密码哈希
- **选择**: PBKDF2 - 平衡安全性和性能，符合项目使用标准库的要求

#### 决策: 随机数（nonce）管理
- **Rationale**: AES-GCM 需要唯一且不可重复的随机数确保安全性
- **选项1**: 生成随机 nonce 并将其与加密数据一起存储
- **选项2**: 使用计数器模式（需要持久化计数器）
- **选择**: 生成随机 nonce 并将其与加密数据一起存储 - 简单且安全

#### 决策: 测试策略
- **Rationale**: 加密解密功能需要全面测试确保正确性和安全性
- **策略**:
  - 单元测试加密/解密函数
  - 集成测试配置加载和解析
  - 跨平台兼容性测试

## 4. Phase 1: 设计与契约 (Design & Contracts)

### 4.1 数据模型 (Data Model)

#### 4.1.1 加密配置值格式
- 类型：字符串
- 格式：`encrypted:<base64-encoded-encrypted-data>`
- 加密数据结构：`[nonce][ciphertext][authentication_tag]`
  - nonce: 12字节（AES-GCM标准）
  - ciphertext: 加密内容
  - authentication_tag: 16字节认证标签

#### 4.1.2 配置结构变化
- 现有配置结构不变
- 敏感字段值可能是加密格式
- 解密后映射到原有字段类型

#### 4.1.3 验证规则
- 加密字段必须以 "encrypted:" 开头
- 加密内容必须是有效的 Base64 编码
- 解密操作必须成功返回明文

### 4.2 API 契约

#### 4.2.1 加密接口
- 函数: `Encrypt(value string, key []byte) (string, error)`
- 输入: 待加密字符串和密钥
- 输出: 格式化的加密字符串或错误
- 作用: 将明文转换为带前缀的加密格式

#### 4.2.2 解密接口
- 函数: `Decrypt(encryptedValue string, key []byte) (string, error)`
- 输入: 带前缀的加密字符串和密钥
- 输出: 解密后的明文或错误
- 作用: 将加密格式转换回明文

#### 4.2.3 配置加载接口
- 函数: `LoadEncryptedConfig()` (*Config, error)
- 输入: 无
- 输出: 解密后的配置对象或错误
- 作用: 读取配置文件并解密所有加密字段
